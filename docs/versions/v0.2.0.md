## Added

### Server Actions (2 new → 9 total)

- `List_PopByConditions(SourceListJson, ConditionsJson, LogicalOperator, SearchFromEnd, …)` — pops the first element matching multiple conditions combined with `AND` (default) or `OR`.
- `List_PopMultipleByConditions(SourceListJson, ConditionsJson, LogicalOperator, …)` — pops every element matching multiple conditions.

Each condition inside `ConditionsJson` is an object: `{path, operator, value, caseSensitive?}`. AND short-circuits `false` on first miss; OR short-circuits `true` on first hit. Empty conditions array returns the source unchanged.

### Search Direction

- `SearchFromEnd` boolean parameter on `List_PopByCondition` and `List_PopByConditions` — pops the LAST match instead of the first. `PopMultiple*` variants always iterate the whole list, so direction is irrelevant to them.

### Array Indexing in Property Paths

- Path segments now support `[n]` array indexing on all property-path inputs (`PropertyName`, `MatchKey`, condition `path` fields).
- Syntax: `Tags[0]`, `Items[-1].Name`, `Groups[0].Members[-1]`, `Data.Values[3].Score`.
- Negative indices count from the end (`[-1]` is last).
- Out-of-range indices, missing intermediate hops, or non-array values evaluate as no-match rather than throwing.

### Case Sensitivity

- `CaseSensitive` boolean now honoured across `List_PopByCondition`, `List_PopMultipleByCondition`, and `List_Difference` (previously partial coverage). Per-condition `caseSensitive` override supported inside `ConditionsJson`.

### Test Suite Growth

- Additional test files added on both platforms (byte-for-byte parity preserved via the O11 adapter):
  - `CaseSensitiveTests.cs`
  - `ArrayIndexPathTests.cs`

Correctness (expected element count or the `updated + popped = source` invariant) is asserted outside the stopwatch to keep parsing out of the timing budget. `List_Difference` with `Contains` uses a 1,000-element pair because that operator is inherently O(A×B).

## Changed

- All Server Action parameter names renamed to **PascalCase** for consistency with OutSystems naming conventions (`SourceListJson`, `PropertyName`, `CaseSensitive`, `PoppedElementJson`, …). The O11 `Iss<Name>` interface still uses `ss<Name>` camelCase mangling; the O11 test project's internal `IListUtils` adapter uses PascalCase so the ODC/O11 test files stay byte-for-byte identical.
- Refactored `ListUtils` (ODC) and `CssListUtils` (O11) into partial classes split by action group. New files on each side:
  - `ListUtils.Index.cs` / `ListUtilsActions.Index.cs` — `List_Pop`, `List_PopMultiple`
  - `ListUtils.Condition.cs` / `ListUtilsActions.Condition.cs` — `PopByCondition`, `PopMultipleByCondition`, `PopByConditions`, `PopMultipleByConditions`
  - `ListUtils.Relational.cs` / `ListUtilsActions.Relational.cs` — `Zip`, `GroupBy`, `Difference`
  - `ListUtils.Helpers.cs` / `ListUtilsActions.Helpers.cs` — `GetPropertyValue`, `NavigateSegment`, `MatchesCondition`, `ParseConditions`, `EvaluateConditions`, `TryCompareNumeric`, `ToCamelCase`, nested `Condition` type, shared `JsonSerializerOptions`
  The original `ListUtils.cs` / `Actions/ListUtilsActions.cs` files are now partial-class shells (no members). No behavioural change.
- `List_Difference` fast paths — every operator except `Contains` now runs in O(A+B) or O(A·L):
  - `Equals` and `NotEquals` use a `HashSet<string>` for O(1) lookup per element.
  - `StartsWith` and `EndsWith` scan the O(|keyA|) prefixes/suffixes of each A key against a `HashSet` of B values.
  - `GreaterThan`, `LessThan`, `GreaterOrEqual`, `LessOrEqual` precompute `min(B)` / `max(B)` once and reduce each per-A test to a single decimal parse plus compare.
  - `Contains` remains O(A×B) — the only operator that would need a suffix trie / Aho-Corasick to beat.
- Replaced every `JsonNode.Parse(node.ToJsonString())` round-trip clone with `JsonNode.DeepClone()` across all Server Actions. Roughly halves the runtime of `List_Zip`, `List_GroupBy`, `List_Pop`, `List_PopMultiple`, and the `Pop*ByCondition*` family on 10 k-element inputs.
- `generate_upload_package.ps1` refactored for clarity (parameterised paths, single `dotnet publish` invocation, explicit size check against the 90 MB ODC Portal limit).
- `ARCHITECTURE.md` expanded — Mermaid processing-flow diagram now covers helpers, multi-condition evaluation, search direction, and property-path navigation; test-file inventory updated for the new files; `List_Difference` fast-path complexity table added.
- `README.md` — new sections for the multi-condition action family, the operator matrix, property-path syntax with array indexing, and the search-direction flag.
