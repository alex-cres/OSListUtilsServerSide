# v0.7.2 (O11)

**Released:** 2026-10-29  
**Forge:** https://www.outsystems.com/forge/component-overview/25935/listutils-o11  
**Platform:** OutSystems 11

> Same functional changes as the ODC release [v0.7.2](./v0.7.2.md). This file lists them from the O11 extension's point of view.

---

## Added

- **201 new xUnit test cases** in the O11 test project (493 → 694), byte-for-byte identical to the ODC suite.
  - `ActionCoverageTests.cs`: per-action contract tests.
  - `InvariantTests.cs`: round-trips, cross-action equivalences, server-culture independence, concurrency, and the malformed-input contract. These matter for O11 servers running a non-English Windows locale.
  - Regression tests for the fixes and the negative-index change below.

## Changed

- **`List_Pop` and `List_PopMultiple` — negative indices now count from the end** (`-1` = last element), matching `List_SplitAt`, `List_UpdateAt`, `List_UpdateMultipleAt`, `List_Slice`, and `[-1]` path indexing.
  - `List_PopMultiple` parses indices with `CultureInfo.InvariantCulture` and removes an element once when a negative and a positive index point to it.
  - **Behaviour change:** a negative index used to be a no-op.
- **XIF regenerated and recompiled.**
  - `xif-spec/spec.json` and the generated `ListUtils.Core.*.cs` sources were rebuilt from `ListUtils.O11`. They were applied to `xif/ListUtils.xif` through the Integration Studio UI automation pipeline: metadata, Update Source Code, logic injection, and Verify and Save (F4).
  - All 814 verifier checks passed after F4 and after the open/close, Ctrl+S, and F4 revert round-trips.
  - The `Index` / `IndicesToPop` parameter descriptions in the extension metadata were updated.
  - The DLL compiled inside the XIF was executed under .NET Framework 4.8 and confirmed to contain both fixes and the negative-index change.
- **O11 documentation** (`docs/platform/o11/documentation.md`, `forge-description.md`) updated for the negative-index behaviour, the `List_GroupBy` / `List_Difference` / `List_Aggregate` edge cases, and the update-action path rules.

## Fixed

- **`List_UpdateAt`, `List_UpdateMultipleAt`, `List_ReplaceWhere` — partial write through a missing array.**
  - A path such as `Items[0].Name` (when `Items` is missing) or `Meta.` used to leave an empty object behind while skipping the write.
  - The write is now aborted before anything is created, and the item is left unchanged.
- **`List_Difference` with `NotEquals` when B has no key values** used to drop every A element. It now keeps all of A.
