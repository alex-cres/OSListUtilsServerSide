## Added

### Server Actions (5 new → 14 total)

Fills the most-requested gaps in native OutSystems list operations.

- `List_Chunk(SourceListJson, ChunkSize) → ChunksListJson` — splits a JSON list into an array of fixed-size sublists (the last chunk may be smaller). Essential for batch integrations, API payload limits, and throttled loops. `ChunkSize <= 0` or an empty source returns `"[]"`.
- `List_DistinctBy(SourceListJson, PropertyName, CaseSensitive) → DistinctListJson` — filters to unique elements by property key (first occurrence wins). Empty `PropertyName` dedupes on the entire item's JSON. Missing keys share a single "null-key" bucket. Uses the existing `GetPropertyValue` walker, so nested paths and array indexing are supported.
- `List_Slice(SourceListJson, Start, End, Step) → SliceListJson` — Python / JavaScript-style slicing.
  - `Start`: negative counts from the end; clamped to list bounds.
  - `End`: negative counts from the end. **`End == 0` is treated as "unspecified"** — for positive `Step` that means "to end of list"; for negative `Step` that means "past the beginning" (matches Python defaults).
  - `Step`: `0` is treated as `1`. Negative walks backward (reverse slice).
- `List_Shuffle(SourceListJson, Seed) → ShuffledListJson` — Fisher-Yates shuffle.
  - `Seed == 0` → `RandomNumberGenerator` (CSPRNG) per swap.
  - `Seed != 0` → deterministic `System.Random(Seed)` for reproducibility.
  - Source list is not mutated.
- `List_UpdateAt(SourceListJson, Index, PropertyName, NewValueJson) → UpdatedListJson, PreviousValueJson` — sets a single property on the item at `Index`. Negative `Index` counts from the end. `PropertyName` supports nested paths and array indexing. Missing intermediate objects are created; arrays are NOT auto-created — a missing or non-array indexing step returns the source unchanged. `NewValueJson` is parsed as JSON, falling back to a raw string when the value is not valid JSON. `PreviousValueJson` is `"null"` when the index is out of range, `PropertyName` is empty, the item is not an object, the property did not exist, OR the property existed with a JSON `null` value (the last two cases are indistinguishable).

### Implementation Files

- ODC: new partial `ListUtils/ListUtils.Transform.cs` hosts the five implementations plus seven private helpers (`NormalizeSliceStart`, `NormalizeSliceEnd`, `ParseValueOrString`, `SetPropertyValue`, `NavigateOrCreateSegment`, `SetTerminalSegment`, `ParseSegment`).
- O11: `ListUtils.O11/Actions/ListUtilsActions.Transform.cs` mirrors the ODC implementation with the net48-specific tweaks (`str.Substring(1)`, explicit `new JsonSerializerOptions { … }`, no target-typed `new()`, no range syntax).
- BCL-only: `System.Security.Cryptography.RandomNumberGenerator` (used by `List_Shuffle` when `Seed == 0`) ships with both net10.0 and net48 BCLs — no new NuGet dependency.

### Test Suite Growth

- `TransformTests.cs` in both test projects — **20 functional tests per platform** (40 total) covering:
  - `List_Chunk`: regular / uneven / oversized / negative / empty source.
  - `List_DistinctBy`: property key, nested path, empty `PropertyName` full-item dedupe, null-key bucket, case-sensitive vs insensitive.
  - `List_Slice`: positive / negative `Start` / negative `End` / `End == 0` sentinel / `Step == 0` / negative `Step` reverse.
  - `List_Shuffle`: `Seed != 0` reproducibility, `Seed == 0` CSPRNG variance, source not mutated.
  - `List_UpdateAt`: positive / negative `Index`, nested path, auto-created missing objects, missing-array short-circuit, PreviousValueJson for missing property vs JSON `null`.
- `LoadTests.cs` grew by 50 tests per platform (100 total) — 10 per new action, driven by the same shared 10,000-element complex JSON structure with the same 300 ms budget.
- Adapter methods for the five new actions added to `internal IListUtils` and its wrapper in `ListUtils.O11.Tests/TestHelpers.cs`.
- Total suite: **620 tests** (310 ODC + 310 O11) — 145 functional + 165 load per platform.
