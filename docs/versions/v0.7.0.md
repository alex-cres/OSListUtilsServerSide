## Summary

Performance release. No new Server Actions, no interface changes, no dependency bumps. Every performance-motivated `DeepClone()` call in the component has been eliminated by a new tail-drain / re-parent pattern (`DrainToArray`), landed across four staged phases with a full change cycle (test-runner → architecture-validator → functional-regression-detector → documentation-updater) and a 100-iteration `tools/LoadTest` perf validation gating each phase.

24 of the 33 Server Actions are now measurably faster on both platforms; the remaining 9 were already at the JSON parse/serialise floor and had no clone to eliminate. Every optimised action improved 41–71 % vs the v0.6.0 baseline on the 20 000-element worst-case scenario. All 986 tests (493 ODC + 493 O11) pass.

## Changed

- `List_PopMultiple` (ODC) and `MssList_PopMultiple` (O11) now detach popped items directly from the parsed `JsonArray` in descending-index order and re-parent them into the output array in ascending order, eliminating two redundant `DeepClone()` calls per popped element. Output shape is unchanged for non-null items — identical JSON bytes. First phase of the performance optimisation series.
- `List_Chunk`, `List_DistinctBy`, `List_Slice`, `List_Shuffle`, `List_Reverse`, `List_Flatten`, and `List_Sample` (ODC) and their `MssList_*` (O11) mirrors now tail-drain the parsed `JsonArray` via a shared `DrainToArray` helper and re-parent the detached refs into the output arrays, removing the per-element `DeepClone()` from every discard-input action. Output shape is unchanged for populated non-null inputs — identical JSON bytes. Second phase of the performance optimisation series.
- `List_Difference`, `List_Intersect`, and `List_Union` (ODC) and their `MssList_*` (O11) mirrors now reuse the shared `DrainToArray` helper to re-parent surviving elements from the parsed input `JsonArray`s into the output array, removing the per-element `DeepClone()` from the set-operation family. Output shape is unchanged for populated non-null inputs — identical JSON bytes. Third phase of the performance optimisation series.
- `List_SplitAt` (index family); `List_PopMultipleByCondition`, `List_PopMultipleByConditions`, `List_Partition`, `List_PartitionByConditions` (condition family); `List_Zip`, `List_GroupBy`, `List_ZipGroupBy`, `List_GroupByMultiple`, `List_ZipGroupByMultiple` (relational family); and `List_ZipMany`, `List_ZipManyGroupBy`, `List_ZipManyGroupByMultiple` (ZipMany family) — plus their `MssList_*` (O11) mirrors — now detach items from the parsed input `JsonArray` and re-parent them into their output arrays via the shared `DrainToArray` pattern, eliminating the per-element `DeepClone()` from every remaining performance-sensitive clone site in the component. Output shape is unchanged for populated non-null inputs — identical JSON bytes. Fourth and final phase of the performance optimisation series. The two remaining `DeepClone()` calls, both in `SetTerminalSegment` (`Transform.cs`, ODC + O11), are intentional: they snapshot the previous value before overwrite for `List_UpdateAt` and `List_ReplaceWhere` and must return an independent copy.

## Fixed

- `List_Chunk`, `List_DistinctBy`, `List_Slice`, `List_Shuffle`, `List_Reverse`, and `List_Sample` (ODC) and their `MssList_*` (O11) mirrors no longer throw `NullReferenceException` when the input array contains JSON `null` literals. `null` elements are now preserved in the output. (`List_Flatten` was already null-safe.)
- `List_Difference`, `List_Intersect`, and `List_Union` (ODC) and their `MssList_*` (O11) mirrors no longer throw `NullReferenceException` when the source arrays contain JSON `null` literals. `null` elements are now preserved through to the output where applicable.
- `List_SplitAt`, `List_PopMultipleByCondition`, `List_PopMultipleByConditions`, `List_Partition`, `List_PartitionByConditions`, `List_Zip`, `List_GroupBy`, `List_ZipGroupBy`, `List_GroupByMultiple`, `List_ZipGroupByMultiple`, `List_ZipMany`, `List_ZipManyGroupBy`, and `List_ZipManyGroupByMultiple` (ODC) and their `MssList_*` (O11) mirrors no longer throw `NullReferenceException` when the source arrays contain JSON `null` literals. `null` elements are now preserved in the output where the action would previously have retained the item. Completes consistent null-literal robustness across all `JsonArray`-consuming actions in the component.

## Implementation

### The `DrainToArray` pattern

A single private static helper lives once in each platform's `Helpers.cs` partial:

```csharp
// Removes every element from `array` and returns the detached refs in original order.
// Tail-drain keeps each RemoveAt at O(1). Callers can re-parent the refs into a fresh
// JsonArray without cloning, since RemoveAt sets each node's Parent to null.
private static JsonNode?[] DrainToArray(JsonArray array)
{
    int n = array.Count;
    var picked = new JsonNode?[n];
    for (int i = n - 1; i >= 0; i--)
    {
        picked[i] = array[i];
        array.RemoveAt(i);
    }
    return picked;
}
```

`JsonArray.RemoveAt(count-1)` is O(1) (no shift) and sets the removed node's `Parent` to `null`. That makes the returned refs safe to re-parent into a fresh output `JsonArray` via `output.Add(ref)` without triggering `InvalidOperationException("Node already has a parent")`. The pattern replaces `output.Add(item.DeepClone())` throughout the codebase, halving allocations and dropping GC pressure.
