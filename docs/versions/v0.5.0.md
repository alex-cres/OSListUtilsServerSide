## Added

### Server Actions (14 new → 29 total)

Fourteen new actions covering aggregation, set operations, split / partition, shape transforms, mass update, and multi-list zip. Every action reuses the existing `GetPropertyValue`, `MatchesCondition`, `TryCompareNumeric`, `ParseConditions`, `EvaluateConditions`, `SetPropertyValue`, and `ParseValueOrString` helpers — no new NuGet dependencies.

#### Aggregations (3)

- **`List_MinBy(SourceListJson, PropertyName, NumericMode) → ElementJson, MinValue, MinIndex`** — returns the element with the smallest value at a property path, plus the raw text of that value and its 0-based index. `NumericMode = true` parses as `decimal` (skipping non-numeric); `NumericMode = false` compares as ordinal case-insensitive text. Ties break to first occurrence. Empty list → `ElementJson = "null"`, `MinValue = ""`, `MinIndex = -1`.
- **`List_MaxBy(SourceListJson, PropertyName, NumericMode) → ElementJson, MaxValue, MaxIndex`** — same as `MinBy` but returns the largest.
- **`List_Aggregate(SourceListJson, PropertyName, Operation) → ResultValue, MatchedCount`** — scalar roll-up over a property. Supports `Sum`, `Avg`, `Min`, `Max`, `Count`, `CountDistinct`. Numeric ops parse each value as `decimal` with `InvariantCulture` and skip non-numeric. `Count` counts non-null values; `CountDistinct` deduplicates by ordinal text. `MatchedCount` reports how many items contributed. Empty result when no items qualified.

#### Set operations (2)

- **`List_Intersect(ListAJson, ListBJson, MatchKey, ComparisonOperator, CaseSensitive) → IntersectionListJson`** — A ∩ B on a keyed property. Preserves A's original order. `Equals` uses `HashSet<string>` for O(A + B); other operators fall back to the pairwise `MatchesCondition` scan.
- **`List_Union(ListAJson, ListBJson, MatchKey, CaseSensitive) → UnionListJson`** — concatenates A + B, dedupes by `MatchKey` (first occurrence wins; A's items appear first). Empty `MatchKey` dedupes by the whole item's JSON.

#### Split / partition (3)

- **`List_SplitAt(SourceListJson, Index) → LeftListJson, RightListJson`** — splits at a boundary. Negative `Index` counts from the end. `Index <= 0` leaves `Left` empty; `Index >= list.Length` leaves `Right` empty.
- **`List_Partition(SourceListJson, PropertyName, TargetValue, ComparisonOperator, CaseSensitive) → MatchingListJson, NonMatchingListJson`** — non-mutating dual of `List_PopMultipleByCondition`. Returns both matching and non-matching sublists in one call.
- **`List_PartitionByConditions(SourceListJson, Conditions: List<Condition>, LogicalOperator) → MatchingListJson, NonMatchingListJson`** — multi-condition version with `AND` / `OR`, same `Condition` structure used by the Pop family (`Path`, `Operator`, `Value`, `CaseSensitive`).

#### Shape (3)

- **`List_Reverse(SourceListJson) → ReversedListJson`** — dedicated reverse. Equivalent to `List_Slice(-1, 0, -1)` but explicit and cheaper.
- **`List_Flatten(ChunksListJson: List<Text>) → FlatListJson`** — concatenates a `List<Text>` of JSON-array strings into a single flat JSON array. Inverse of `List_Chunk` — feed Chunk's output directly and get back the original list. Non-array entries (empty strings, malformed JSON, JSON objects) are silently skipped.
- **`List_Sample(SourceListJson, SampleSize, Seed) → SampleListJson`** — random subset of `SampleSize` elements without replacement. Uses partial Fisher-Yates over a working copy — source is not mutated. `Seed = 0` → `RandomNumberGenerator` (CSPRNG); `Seed != 0` → deterministic `System.Random(Seed)`. `SampleSize <= 0` returns empty; `SampleSize > list.Length` returns the full list in shuffled order.

#### Mass update (2)

- **`List_ReplaceWhere(SourceListJson, Conditions: List<Condition>, LogicalOperator, UpdateProperty, NewValueJson) → UpdatedListJson, MatchCount`** — applies the same property update to every element that satisfies a multi-condition filter. Takes the same `List<Condition>` + `LogicalOperator` (`AND` / `OR`) shape used by `List_PopByConditions`, so users can mix numeric and text operators, target nested paths, and set per-condition case sensitivity in a single call. Reuses `SetPropertyValue` from `UpdateAt`, so nested update paths and missing intermediate objects work identically. `MatchCount` reports how many elements matched the combined condition and were updated. Empty conditions list is a no-op.
- **`List_UpdateMultipleAt(SourceListJson, IndicesToUpdate, PropertyName, NewValueJson) → UpdatedListJson, UpdatedCount`** — updates the same property to the same value on multiple indices. Comma-separated 0-based indices (`"1,3,5"`); negative indices count from the end; out-of-range and duplicate indices are silently skipped.

#### Multi-list zip (2)

- **`List_ZipMany(ListsJson: List<Text>, KeyNamesJson: List<Text>) → ZippedListJson`** — N-list generalisation of `List_Zip`. Each entry in `ListsJson` is one input list's JSON-array string; each entry in `KeyNamesJson` is the field name used for that list in the output objects. Output length is `min(input lengths)`. Missing key names default to `"Items0"`, `"Items1"`, …
- **`List_ZipManyGroupBy(ListsJson: List<Text>, KeyPropertiesJson: List<Text>, KeyNamesJson: List<Text>, CaseSensitive) → GroupedListJson`** — N-list generalisation of `List_ZipGroupBy`. Cogroups an arbitrary number of lists by a shared key value across all of them. `KeyPropertiesJson[i]` is the property path in `ListsJson[i]` that supplies the key; `KeyNamesJson[i]` is the output array label for that list within each group. Missing key values share a single `"Unknown"` bucket. Groups appear in first-seen order across all inputs.

### API ergonomics — typed `Condition` Structure + named-constant classes

- New `Condition` Structure (`Path`, `Operator`, `Value`, `CaseSensitive`) — a first-class OutSystems Structure used by every multi-condition action, replacing hand-authored JSON strings. The four multi-condition actions (`List_PopByConditions`, `List_PopMultipleByConditions`, `List_PartitionByConditions`, `List_ReplaceWhere`) now accept `Conditions : List<Condition>` instead of `ConditionsJson : Text`. Consumers get compile-time field checking and IDE autocomplete instead of hand-authored JSON. The list-empty short-circuit is preserved: an empty `Conditions` returns the source list byte-for-byte unchanged.
- Three named-constant helper classes surface every operator string as an ODC / O11 constant, so callers get IDE autocomplete and compile-time typo detection:
  - `Operators` — `Equals`, `NotEquals`, `Contains`, `StartsWith`, `EndsWith`, `GreaterThan`, `LessThan`, `GreaterOrEqual`, `LessOrEqual`
  - `LogicalOperators` — `AND`, `OR`
  - `AggregateOperations` — `Sum`, `Avg`, `Min`, `Max`, `Count`, `CountDistinct`
- Every internal operator string literal across production code and the full test suite has been migrated to these constants. Runtime behaviour is unchanged — the backwards-compatible symbol aliases (`!=`, `>`, `<`, `>=`, `<=`) are still accepted.
- `ARCHITECTURE.md` — the single ODC processing flow diagram is now split into six per-partial Mermaid diagrams (Index / Condition / Relational / Transform / Aggregate / ZipMany) plus a shared-helpers diagram, for easier navigation.

### Implementation Files

- ODC: new partials `ListUtils/ListUtils.Aggregate.cs` (MinBy, MaxBy, Aggregate) and `ListUtils/ListUtils.ZipMany.cs` (ZipMany, ZipManyGroupBy). Existing partials extended:
  - `ListUtils.Index.cs` — SplitAt
  - `ListUtils.Condition.cs` — Partition, PartitionByConditions
  - `ListUtils.Relational.cs` — Intersect, Union
  - `ListUtils.Transform.cs` — Reverse, Flatten, Sample, ReplaceWhere, UpdateMultipleAt
- O11: `ListUtilsActions.Aggregate.cs`, `ListUtilsActions.ZipMany.cs`, and the parallel additions to `Index / Condition / Relational / Transform`. All net48-safe (no target-typed `new()`, no range syntax, explicit `System.Collections.Generic` and `System.Globalization` usings).

### Test Suite Growth

- 94 new functional tests (47 ODC + 47 O11) in `V050Tests.cs` — 2–6 per action covering happy paths, edge cases (empty inputs, missing properties, empty conditions list), and semantic contracts (Union first-occurrence wins, ReplaceWhere multi-condition AND/OR combining, ZipMany truncation to shortest, ZipManyGroupBy "Unknown" bucket). Includes explicit byte-identity guards for the empty-`Conditions` short-circuit on all four multi-condition actions and a `[Theory]` sweep over the five symbol operator aliases (`!=`, `>`, `<`, `>=`, `<=`) through the typed API.
- 140 new load tests (70 ODC + 70 O11) — 5 per new action — appended to `LoadTests.cs`. Same shared 10 000-element input structure, same 300 ms budget. Correctness verified outside the stopwatch.
- Adapter methods for all 14 new actions added to `internal IListUtils` and its wrapper in `ListUtils.O11.Tests/TestHelpers.cs`, including three `List<string>` parameter methods (`List_Flatten`, `List_ZipMany`, `List_ZipManyGroupBy`), plus shadow `Condition` / `Operators` / `LogicalOperators` / `AggregateOperations` types so ODC and O11 test files remain byte-for-byte identical.
- Total suite grew from 662 to **922 tests** (461 ODC + 461 O11).
