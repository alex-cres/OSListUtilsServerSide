## Summary

Behaviour-and-correctness release. Negative indices now count from the end in `List_Pop` and `List_PopMultiple`. Two data bugs are fixed: a partial write through a missing array in the update actions, and `List_Difference` with `NotEquals` when B has no key values. A documentation refresh covers all 33 actions, and the test suite grows from 493 to 694 tests per platform (1,388 total). No new Server Actions, no signature changes, no dependency changes.

## Added

- **201 new xUnit test cases per platform** (493 → 694 on ODC and O11, all byte-for-byte identical between the two test projects).
  - `ActionCoverageTests.cs` (61 tests) — per-action contract tests from a one-by-one review of all 33 actions. They focus on the thinnest-covered actions (`Partition`, `MaxBy`, `Union`, `Intersect`, `UpdateMultipleAt`, `ZipManyGroupBy`), defaults, case-sensitivity flags, null / empty inputs, ordering, and keyless or non-object items.

## Changed

- **`List_Pop` and `List_PopMultiple` — negative indices now count from the end.**
  - Previously `List_Pop` treated a negative `Index` as out of range (source returned unchanged, `PoppedElementJson = "null"`), and `List_PopMultiple` silently ignored negative entries.
  - Now `-1` is the last element, consistent with `List_SplitAt`, `List_UpdateAt`, `List_UpdateMultipleAt`, `List_Slice`, and `[-1]` path indexing.
  - Negatives still out of range after normalisation keep the out-of-range behaviour.
  - In `List_PopMultiple`, a negative and a positive index for the same element (e.g. `"2,-1"` on 3 items) remove it once, and indices are parsed with `CultureInfo.InvariantCulture`.
  - **Behaviour change:** callers that relied on a negative index being a no-op will now remove an element. The `Index` / `IndicesToPop` parameter descriptions were updated.
- **Documentation refresh to match the 33-action surface.**
  - `README.md` has a full parameter reference for all 33 actions (15 sections were missing) and a complete "How It Works" table.
  - `ARCHITECTURE.md` diagrams and file tables are corrected: Sample uses a partial Fisher-Yates, Shuffle / Reverse use tail-drain, only `List_Difference` has the fast paths, and the non-existent `ParseConditions` helper is removed.
  - `docs/platform/odc/documentation.md` is rewritten with PascalCase parameter names, and `docs/platform/odc/forge-description.md` covers every action.
  - Edge-case behaviour is now documented: `List_GroupBy` case sensitivity and the `"Unknown"` group, `List_Difference` keeping keyless items, and `List_Aggregate` treating an unknown operation as `Sum` with case-sensitive `CountDistinct`.

## Fixed

- **`List_UpdateAt`, `List_UpdateMultipleAt`, `List_ReplaceWhere` — partial write through a missing array.**
  - A path that needed to create an object and then index into an array (e.g. `Items[0].Name` or `Meta.Tags[0]` on an item without `Items` / `Meta`) used to leave an empty object behind (`{"Id":1,"Items":{}}`) while skipping the write. The same happened for an empty path segment after a missing object (`Meta.`, `Meta..Name`).
  - The shared `SetPropertyValue` helper now runs a read-only pre-check (`CanWriteWithoutPartialCreation`) and aborts before creating anything. The item is left unchanged and `PreviousValueJson = "null"`.
  - Object-only paths are still auto-created.
- **`List_Difference` with `NotEquals` when B has no key values.**
  - Every A element used to be dropped when B was empty or none of its items had `MatchKey`. The fast path now evaluates "B contains a key different from A's key", so all of A is kept.
  - Results are unchanged whenever B contains at least one key value.
