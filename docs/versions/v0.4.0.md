## Added

### Server Actions (14 new → 28 total)

Every one of the fourteen existing actions gains a matching `*InPlace` variant. Each accepts the primary list parameter by C# `ref` (mapped to **Input/Output** in OutSystems), mutates the caller's variable directly, and delegates to the corresponding non-InPlace action for the actual logic. Secondary outputs (`PoppedElementJson`, `PoppedElementsJson`, `PreviousValueJson`) stay as normal Output parameters.

This lets consumers avoid the `MyList = ListUtils.Action(MyList).OutputList` reassignment pattern — one node, one variable, no reassignment.

- **Pop family (6 InPlace variants):** `List_PopInPlace`, `List_PopMultipleInPlace`, `List_PopByConditionInPlace`, `List_PopMultipleByConditionInPlace`, `List_PopByConditionsInPlace`, `List_PopMultipleByConditionsInPlace`.
- **Relational (3 InPlace variants):** `List_ZipInPlace` (mutates `ListAJson` with the paired result), `List_GroupByInPlace` (mutates `SourceListJson` with the grouped `{Key, Items}` array), `List_DifferenceInPlace` (mutates `ListAJson` with A − B).
- **Transform (5 InPlace variants):** `List_ChunkInPlace`, `List_DistinctByInPlace`, `List_SliceInPlace`, `List_ShuffleInPlace`, `List_UpdateAtInPlace`.

Behaviour is byte-for-byte identical to the base action; only the parameter direction changes.

### Implementation Files

- ODC: new partial `ListUtils/ListUtils.InPlace.cs` hosts all 14 delegating implementations.
- O11: `ListUtils.O11/Actions/ListUtilsActions.InPlace.cs` mirrors the ODC file.
- Each InPlace body is 2 – 3 lines: call the corresponding base action into a local `out` variable, then assign it back to the `ref` parameter.

### Test Suite Growth

- `InPlaceTests.cs` in both test projects — **45 functional tests per platform** (90 total):
  - **Ref-mutation identity (14 tests):** one per InPlace action, verifies the caller's variable is replaced with the transformed / mutated JSON.
  - **Full parity matrix (14 tests):** one per InPlace variant asserting byte-equal primary output AND byte-equal secondary output vs the corresponding base action on identical input.
  - **Ref semantics (14 tests):** chained pops shrink the list by the expected amount; chained-same-seed shuffle is shuffle-of-the-shuffle; fresh input + same seed is fully deterministic across three calls; `Chunk → Slice` composes; `DistinctBy → GroupBy` composes; `SearchFromEnd` toggle across chained pops; `PopInPlace` secondary output is not aliased to the ref; `UpdateAtInPlace` `PreviousValueJson` is a pre-mutation snapshot; chained `UpdateAt + Pop` composes; malformed JSON on `ShuffleInPlace` / `SliceInPlace` throws `JsonException` (propagated through the delegation); `ZipInPlace` / `DifferenceInPlace` leave `ListB` untouched; ref assignment produces a new string reference (caller's original snapshot in a separate variable is preserved).
  - **Short-circuit / edge (3 tests):** `ShuffleInPlace` on empty input becomes `"[]"`; `UpdateAtInPlace` with out-of-range Index leaves the ref unchanged; `PopInPlace` with out-of-range Index leaves the ref unchanged.
- `LoadTests.cs` grew by 42 tests per platform (84 total) — 3 per InPlace variant × 14 variants — driven by the same shared 10,000-element complex JSON input with the same 300 ms budget. Each takes an O(1) local copy of the shared static input so tests remain isolated when run in parallel and the shared data is never mutated across tests.
- Adapter methods for the 14 new InPlace actions added to `internal IListUtils` and its wrapper in `ListUtils.O11.Tests/TestHelpers.cs`, forwarding `ref` through to the `MssList_*InPlace` methods.
- Total suite: **794 tests** (397 ODC + 397 O11) — 190 functional + 207 load per platform.
