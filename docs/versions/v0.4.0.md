## Added

### Server Actions (1 new → 15 total)

- **`List_ZipGroupBy(ListAJson, ListBJson, KeyPropertyA, KeyPropertyB, KeyNameA, KeyNameB, CaseSensitive) → GroupedListJson`** — cogroup / two-list join by a shared key. For every distinct key value across both lists, emits one group object containing the key plus a named array of items from `ListA` and a named array of items from `ListB`.

  **Output shape per group:**

  ```json
  {
    "Key": "<keyValue>",
    "<KeyNameA>": [ ...ListA items with this key... ],
    "<KeyNameB>": [ ...ListB items with this key... ]
  }
  ```

  **Semantic details:**

  - Uses the shared `GetPropertyValue` walker, so nested paths and array indexing work in both key selectors (`Customer.Id`, `Meta.Tags[0]`, `Refs[-1].Code`).
  - The two `KeyProperty*` parameters can differ — e.g. join `CustomerId` on `ListA` with `customer_id` on `ListB`.
  - Ordering: A's keys first (in A's order), then B-only keys (in B's order).
  - Missing key → single `"Unknown"` bucket (matches `List_GroupBy`).
  - Blank `KeyNameA` / `KeyNameB` fall back to `"ItemsA"` / `"ItemsB"`.
  - `CaseSensitive` defaults to `false` (matches `List_Difference`).
  - Complexity: O(A + B), single pass per side.

  **Use case:** "orders + payments per customer", "invoices + line-items per PO", "questions + answers per topic" — scenarios that would otherwise need two `For Each` loops with nested lookups.

## Pre-release notes (context for readers tracking pre-Forge commits)

Two internal-only decisions made during the v0.3.0 → v0.4.0 window are worth noting for anyone reviewing the git history — neither affects the shipped surface:

- **`List_Chunk` output shape refined during v0.3.0.** The output changed from a single `Text` (nested JSON array) to `List<Text>` (each entry a standalone JSON array), so consumers can `JSON Deserialize` each entry directly into their Structure List without unwrapping a `List of List`. The refinement was folded into the v0.3.0 signature — `docs/versions/v0.3.0.md` already reflects the final `List<Text>` shape.
- **14 `*InPlace` (Input/Output) variants were prototyped and withdrawn.** They compiled and passed tests locally, but the ODC Portal upload validation rejects any `[OSAction]` with a C# `ref` parameter (error `OS-ELG-MODL-05016` — *"Passing parameters by reference is not supported"*). The SDK's build-time Roslyn analyzers do NOT catch this, so it was only surfaced at Portal upload. Constraint recorded in `.github/rules/architecture-rules.md` § 5 and the architecture-validator now blocks `ref` at Stage 2 of the change cycle. Consumers should keep using the classic `MyList = ListUtils.Action(MyList).OutputList` reassignment pattern.
